# Bump donations-api-client to 2.4.0

## Context

The frontend pins `@jorgetroya80/donations-api-client@2.3.0`. The newest published version is
**2.4.0** (2026-11-23). The client's version always matches the API release tag.

What changed in `donations-api` between `v2.3.0` and `v2.4.0`:

| Commit    | Change                                                                                                                                                   | Effect on the client                                                                      |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `3cf121f` | Append-only audit log (#58): new `audit_log` table (`V9`), `AuditService.record()` called on create/update in Donation, Donor, Expense and User services | None. No controller, DTO or `packages/api-client/` file is touched; no read endpoint yet. |

Evidence:

- `diff -ru` of the 2.3.0 and 2.4.0 `dist/` is **empty (0 lines)**. The generated contract is
  identical.
- The service diffs only add an `auditService.record(...)` call before the existing event emit.
  Return values and response bodies are unchanged.
- `UserRepository.findIdByUsername` is new and internal (resolves the acting user for the audit row).

**Outcome:** the frontend runs on client 2.4.0 with no code changes in `src/`.

## Files

| File                 | Change                                                          |

## Dependency graph

```
install 2.4.0 ── diff generated dist/ vs 2.3.0 (empty)

```

## Decisions

- **No code changes.** The type diff is empty and no response shape changed, so any edit in
  `src/` would be scope creep.
- **No audit UI.** The API exposes no endpoint to read the audit log yet. A history view waits
  for that endpoint.
- **Commit type `fix(deps):`**, matching the 2.3.0 bump, so release-please cuts a patch.

## Phases

### Phase 1: Bump (`fix(deps):`)

1. Done: on branch `chore/api-client-2.4.0`, `pnpm add -E @jorgetroya80/donations-api-client@2.4.0`.
2. Done: `diff -ru` against the 2.3.0 snapshot is empty.
3. Run `pnpm run check`, `pnpm run typecheck`, `pnpm run test` and `pnpm run build`.
4. Commit `fix(deps): bump donations-api-client to 2.4.0` together with this plan, then open a PR.

**Acceptance criteria:** `package.json` and `pnpm-lock.yaml` pin 2.4.0, all four checks pass,
and the PR CI is green.

### Checkpoint

- [ ] Optional smoke test against an API running 2.4.0 (local fullstack): log in, create and
      edit a donor, a donation and an expense (writes now also insert audit rows; expect no
      error or slowdown).

## Risks

| Risk                                                              | Impact | Mitigation                                                              |
| ----------------------------------------------------------------- | ------ | ----------------------------------------------------------------------- |
| Audit insert fails and rolls back a write (e.g. missing V9 table) | Low    | Flyway applies `V9` on API start; `AuditLogTest` covers the write path. |
